动态 Teacher / Ref 刷新：Sample-Routed OPSD 后续方案

本文档讨论在当前 K=8 rollout + GRPO + SDPO/OPSD 框架上增加 阶段式 teacher / ref 权重刷新 的可行性。 核心思想是：不要让 teacher 永远停留在旧 checkpoint，也不要让 ref 永远压制 student 的后续探索； 但 teacher 与 ref 的职责不同，刷新节奏必须分开设计。

任务：遥感 bbox grounding 基础方法：Sample-Routed GRPO+SDPO 新增机制：teacher/ref stage refresh 状态：讨论方案，未改训练代码 更新日期：2026-05-21

1. 当前实验证据

目前全量训练结果已经说明，student 的单次 greedy 能力有明显提升， 但同一个 checkpoint 的 best-of-8 oracle 仍显著高于 greedy。 这意味着模型的采样分布中仍包含更强 bbox，只是单次策略还没有稳定选择它们。

关键判断： 如果 teacher 仍停留在较旧 checkpoint，后期 failed / ambiguous 样本的纠偏信号可能不再足够强； 如果 ref 永远不更新，KL 锚点也可能限制 student 继续向更高 oracle 上限靠近。

2. 为什么 EMA Teacher 不一定足够

常规 self-distillation 中，teacher 通常用 EMA 缓慢跟随 student。 这种设计的优点是稳定：teacher 不会因 student 的短期波动而快速退化； 但在当前任务里，它也可能带来两个问题。

问题 表现 对当前任务的影响
teacher 上限滞后 student 已经在指定遥感数据集上变强，但 teacher 仍接近旧分布。 failed route 的 teacher correction 可能只能给出保守答案，不能推动模型接近新 oracle 上限。
后期指导变弱 训练 reward / greedy 指标增长变慢，teacher loss 仍存在但不再提供新增信息。 SDPO/OPSD 变成稳定项，而不是提升项。
无法利用阶段性最佳 student 某个 checkpoint 的 best-of-8 oracle 已明显上升，但 teacher 未及时吸收这部分能力。 下一阶段仍在用旧老师纠偏，浪费已经出现的候选空间能力。
基本方向： 保留 EMA 或固定 teacher 的稳定性，但在阶段边界上允许 teacher 刷新成经过验证的强 student snapshot。 这更像 checkpoint bootstrapping，不是每 step 动态追随。

3. Teacher 与 Ref 不能同等对待

这个方案最重要的设计原则是：teacher 可以更积极刷新，ref 必须更保守刷新。 因为它们在训练里的职责完全不同。

模型 职责 刷新收益 刷新风险 推荐策略
Teacher model 为 failed / ambiguous 轨迹提供更强分布、top-k KL 或 hint correction。 teacher 变强后，低质量样本的纠偏信号更贴近当前数据集上限。 如果刷新到不稳定 student，可能把错误偏好也蒸馏回去。 阶段式刷新，要求验证集 greedy 不退化、parse/valid 稳定、oracle 上限不下降。
Ref model GRPO 的 KL 锚点，限制 student 分布不要漂移过快。 当旧 ref 已经明显过时，刷新 ref 可以释放后续探索空间。 过于频繁刷新会周期性清空 KL 约束，可能导致 reward hacking、格式退化或分布漂移。 只在阶段边界或 KL 长期压制学习时刷新，并设置 cooldown。
不建议： 不建议在训练增长变慢时无条件同时同步 teacher 和 ref。 teacher 同步主要是提高纠偏上限；ref 同步是重置 trust region。 两者同步过频，会让训练变成“自己给自己放行”。

4. 推荐机制：阶段式 Refresh

4.1 三档刷新策略

策略 动作 适用时机 预期效果
Teacher-only refresh teacher_model = student_snapshot，ref 不变。 student greedy 或 oracle 明显高于旧 teacher，且训练稳定。 增强 failed route 的 teacher correction，同时保留原 ref 的 KL 稳定性。
Ref-only refresh ref_model = student_snapshot，teacher 不变或已刷新。 KL 长期偏高、clip/region ratio 表明旧 ref 正在压制学习。 释放下一阶段探索空间，但需要严格监控格式和 reward hacking。
Dual refresh teacher_model = ref_model = student_snapshot。 一个训练阶段结束后，验证指标明确提升，准备进入下一轮 bootstrapping。 把新 student 作为下一阶段的老师和锚点，适合 stage-to-stage 继续训练。

4.2 触发条件

触发 refresh 不应只看训练 loss 下降慢，而应组合看 greedy、oracle、route、KL 与格式稳定性。 

teacher_refresh_candidate =
    val_greedy_iou50 >= best_teacher_iou50 + delta_greedy
    and val_parse_rate >= 0.995
    and val_valid_rate >= 0.995
    and recent_sdpo_loss is finite
    and no severe reward regression

ref_refresh_candidate =
    teacher_refresh_candidate
    and kl_mean has been high for patience windows
    and greedy plateau persists
    and oracle_gap remains positive
    and cooldown since last ref refresh is satisfied
信号 含义 建议判断
greedy plateau 单次输出增长变慢。 连续若干 eval window 内 IoU@0.5 提升小于阈值。
oracle gap 多采样上限仍高于 greedy。 如果 oracle - greedy 仍大，说明压缩空间存在。
route_failed / route_ambiguous 仍有大量需要纠偏的轨迹。 failed/ambiguous 不低时，teacher refresh 更可能有效。
KL / clip ratio ref 是否阻碍更新。 KL 长期偏高时考虑 ref refresh；KL 正常时不急于动 ref。
parse_rate / valid_rate 格式与 bbox 合法性。 必须保持稳定，否则禁止 refresh。

为了确认收益来自 teacher refresh、ref refresh 还是单纯继续训练， 下一轮实验应拆成清晰对照，而不是直接上复杂动态策略。

B：Teacher refresh base_rsfull_e1 checkpoint-1740 checkpoint-1740 旧 ref 验证强 teacher 是否改善 failed-route correction。 greedy 上涨、oracle gap 缩小，且 KL 稳定。
C：Teacher + Ref refresh base_rsfull_e1 checkpoint-1740 checkpoint-1740 checkpoint-1740 验证重置 KL 锚点是否释放进一步提升空间。 reward 上升是否转化为 greedy，而不是只扩大探索。
D：ck80 强初始化 refresh ck80_rsfull_e1 checkpoint-1740 ck80_rsfull_e1 checkpoint-1740 旧 ref 或同 checkpoint 验证当前 rs_full greedy 最强模型是否还能通过 bootstrapping 继续提升。 能否超过 IoU@0.5=0.7759，并接近 base oracle 0.8285。

5.1 立即执行的 800-step 阶段验证

当前最直接、解释性最强的一步，是基于 base_rsfull_grpo_srpo_e1 checkpoint-1740 继续跑 800 steps，并把 teacher 与 ref 都刷新到同一个 checkpoint。 这个实验并不试图一次性证明完整动态 refresh 策略，而是先验证 stage-to-stage checkpoint bootstrapping 是否能继续提升 greedy 指标。

解释边界： 这个实验同时刷新 teacher 与 ref，因此如果指标上涨，说明 stage refresh 方向有效； 但还不能拆分 teacher refresh 与 ref refresh 的单独贡献。 后续仍需要 teacher-only refresh 与 teacher+ref refresh 消融。

6. 训练流程草案

Stage t:
  student = checkpoint_t
  teacher = teacher_t
  ref     = ref_t

  run GRPO + SDPO for N steps or 1 epoch
  periodically evaluate:
    greedy@val
    oracle@8 on a subset
    parse_rate / valid_rate
    route_good / route_failed / route_ambiguous
    kl_mean / sdpo_loss / reward

  choose best student snapshot S*

  if teacher_refresh_condition(S*) is true:
      teacher_{t+1} = S*
  else:
      teacher_{t+1} = teacher_t or EMA(teacher_t, S*)

  if ref_refresh_condition(S*) is true:
      ref_{t+1} = S*
      apply KL beta warmup in next stage
  else:
      ref_{t+1} = ref_t

  student_{t+1} = S*
  continue next stage
组件 建议默认值 理由
refresh 粒度 epoch 边界或固定 stage 边界 避免训练中途频繁加载大模型和破坏优化连续性。
teacher refresh 允许每 stage 一次 teacher 是上限提供者，可以相对积极。
ref refresh 每 1-2 个 stage 至多一次 ref 是 KL 稳定器，刷新必须保守。
KL beta ref refresh 后 warmup 避免 ref 刚刷新后 KL 约束突然失效或过强。
oracle eval 先小子集 K=8，关键 checkpoint 再全量 控制评测成本，同时监控候选空间上限。

7. 风险与保护

风险 触发原因 保护策略
错误自强化 student snapshot 在某些类别或尺寸上退化，但被刷新成 teacher。 按类别、面积分桶验证；只用全局和分桶都不退化的 snapshot。
KL 约束失效 ref 频繁同步成 student。 ref refresh cooldown；刷新后 KL beta warmup；监控 reward hacking。
探索变强但 greedy 不升 ref refresh 释放了采样空间，但单次策略没有学会选择。 增加 good route GRPO 权重，或加强 best-sibling / teacher correction 压缩。
teacher 过度追随 teacher 每次都同步最新 student，失去平滑作用。 只同步 best validation snapshot；非关键 stage 使用 EMA 或固定 teacher。
评测成本过高 每次都全量 K=8 oracle。 训练中用固定子集 oracle@8，最终 checkpoint 再全量评测。

8. 成功标准

这个策略真正成功，不是 teacher/ref 同步本身成功，而是它能让 greedy 更接近 oracle。 

primary_success:
  greedy_iou50_after_refresh > greedy_iou50_continue_baseline
  and parse_rate >= 0.995
  and valid_rate >= 0.995

strong_success:
  oracle_gap_after_refresh < oracle_gap_before_refresh
  and greedy_iou70 improves
  and category/area bucket metrics do not regress

failure_case:
  oracle@8 increases but greedy does not
  or parse/valid drops
  or KL/ref refresh causes unstable reward spikes
最终目标： 让每一轮 checkpoint 都把上一轮 best-of-8 中偶然出现的强 bbox 能力压缩回单次 greedy 输出。 teacher refresh 负责提高纠偏信号上限；ref refresh 只在旧 KL 锚点阻碍后续学习时重置训练阶段。
