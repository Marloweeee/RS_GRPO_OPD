GRPO+SDPO 不同视觉提示模式消融实验计划

目标是在全量遥感目标定位数据上，固定 GRPO 与 SDPO 的训练策略，仅改变 SDPO teacher 侧视觉提示形态，验证 gaussian、soft_window、jitter_box、zoom_in 对最终 greedy student 与 best-of-8 上限的影响。

计划日期：2026-05-22 模型：Qwen3-VL-4B-Instruct 训练：GRPO + SDPO 变量：OPSD_MASK_MODE

核心结论先验

实验主问题
提示强度
teacher 看到的视觉提示越强，KD 信号可能越准，但也可能和 student 部署输入产生更大的分布差异。

IoU@0.5

上限指标
best-of-8
对最优 1-2 个模式追加 best-of-8 oracle，判断候选空间是否随提示模式变好。
执行前置检查：当前 4B GRPO+SDPO worker 已支持 OPSD_MASK_MODE、OPSD_JITTER_RATIO、OPSD_HINT_BOX_COLOR 等参数，但现有 launcher 没有显式透传这些变量到 rjob。正式执行前需要新增一个专用 ablation launcher，或修改 launcher 的 --set-env 列表，确保每个 rjob 真正使用对应模式，避免所有实验都退回 worker 默认的 gaussian。

实验假设

  • H1：gaussian 和 soft_window 都能给 teacher 提供连续空间先验，可能比硬框更稳定；其中 soft_window 不画框，泄漏更少，若性能接近或超过 gaussian，说明 SDPO 不依赖精确框线提示。
  • H2：jitter_box 用抖动框给 teacher 近似区域，可能降低对 GT 框线的过拟合，让 teacher 指导更接近 rollout 中的错误修正场景；但抖动过大可能降低 teacher 的定位质量。
  • H3：zoom_in 给 teacher 最强的局部可见性，可能提升短期 KD 信号；但黑掉上下文会造成 teacher/student 输入分布差异，可能影响 student 单次输出泛化。
  • H4：如果某种提示模式的 greedy 指标没有明显提高，但 best-of-8 oracle 明显提高，说明它主要改善候选空间而不是单次选择能力，后续应结合选择器或更强的组内蒸馏策略。

执行流程

  1. 准备专用 ablation 脚本。基于 tools/training/launch_qwen3_4b_base_rsfull_grpo_sdpo_2node_rjob.sh 和 tools/training/run_qwen3_4b_base_rsfull_grpo_sdpo_2node_worker.sh，新增独立脚本，不污染现有训练入口。launcher 必须显式透传 OPSD_MASK_MODE、OPSD_HINT_MODE、OPSD_GAUSSIAN_SIGMA_RATIO、OPSD_JITTER_RATIO、OPSD_HINT_BOX_COLOR、SDPO_*、GRPO_BETA 等变量。
  2. 做短步 smoke。每个模式先用 MAX_STEPS=20 或 MAX_STEPS=40 跑一次，检查日志中打印的 opsd_mask_mode、SDPO route 指标、mask cache 文件是否符合预期。smoke 输出放到 /data/codes/gui_grounding/data/logs/tmp。
  3. 全量训练。四个核心模式全部从同一个 4B base 初始化，使用全量训练集跑 1 epoch。优先并发 2 个 rjob，避免一次占用过多机器；若 gui_agent 不足，则切到 aos。
  4. 全量 greedy 评估。每个模式训练完成后，取最终 checkpoint 和倒数第三个 checkpoint 分别评估 IoU@0.5/0.6/0.7/0.8/0.9，避免最后保存点异常造成误判。
  5. best-of-8 评估。对 greedy 排名前 2 的模式，追加 num_rollouts=8、temperature=0.7、top_p=0.95 的 best-of-8 oracle 评估；如第三名和第二名差距小于 0.003，也纳入 best-of-8。
  6. 结果归档。把每个实验的 checkpoint 路径、rjob 日志、summary、IoU sweep、best-of-8 结果补充到 rs_full_model_metrics_summary.html，并在本计划文件中追加执行结果表。

评估与判定规则

  • 主判据：全量测试集 greedy student 的 IoU@0.5。若某模式相比当前 4B GRPO+SDPO 单阶段或两阶段基线提升超过 0.003，视为值得继续放大验证。
  • 稳健性判据：同时查看 mIoU、IoU@0.7、IoU@0.8。如果只提升 IoU@0.5 而高阈值下降，说明可能只是粗定位变好，精细 bbox 不一定变好。
  • 采样上限判据：best-of-8 oracle 的 IoU@0.5 与 greedy 的 gap。gap 越大，说明模型能采到好框但单次选择不足；gap 越小，说明策略分布更集中。
  • 训练诊断：记录 sdpo/route_failed、sdpo/route_good、sdpo/iou_mean、sdpo/loss。如果某模式 greedy 低但 teacher route 指标好，优先检查 teacher/student 输入 gap；如果 route 本身差，说明提示不够强或不稳定。
  • 失败处理：如果某个模式训练中断，优先评估已保存的倒数第三个 checkpoint；如果没有有效 checkpoint，再重跑该模式，不把不完整结果混入主表。

预期结果解释

如果 soft_window 最好：说明 SDPO 更需要“区域级软提示”而不是精确框线，后续应围绕 sigma、亮度衰减和无框提示继续搜索。
如果 jitter_box 最好：说明“有噪声的近似 teacher hint”比精确 GT hint 更适合让 student 学会纠错，后续可做 jitter_ratio=0.1/0.2/0.3 扩展实验。
如果 gaussian 或 zoom_in 最好：说明当前模型仍依赖较强 teacher 视觉先验；后续需要检查 best-of-8 gap，判断是否继续加强蒸馏，还是引入选择器把采样上限转化为单次性能。
如果四个模式都接近 GRPO-only：说明当前 SDPO loss 或 teacher/ref 刷新机制可能没有充分生效，应优先排查 SDPO mask 是否进入 teacher 输入、sdpo_sequence_mask 是否覆盖失败样本、teacher KL 权重是否过弱。
