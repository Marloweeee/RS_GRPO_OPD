全量数据 GRPO-only 验证实验计划

目的：在已经验证“只用 OPD 不如 GRPO+OPD”的基础上，补齐“只用 GRPO”的关键对照组， 判断最终收益到底来自组内强化学习本身，还是来自 OPD/teacher 分布校正，或者二者叠加。

1. 实验问题

当前证据链还缺一个纯 GRPO baseline。我们已有或计划已有三类结果：

实验组 训练信号 回答的问题
OPD-only teacher visual hint / distillation，不做组内 RL 单纯靠 teacher hint 能否带来足够提升？
GRPO-only 8 rollouts + bbox geometry reward + GRPO advantage，不做 teacher/OPD 只靠组内强化学习，模型能学到多少 bbox 选择能力？
GRPO+OPD / GRPO+SDPO GRPO 主目标 + 低质量样本 teacher 分布校正 teacher/OPD 是否补足 GRPO 对坏样本学习不足的问题？
核心判断：如果 GRPO-only 明显弱于 GRPO+OPD，说明 teacher/OPD 对低质量轨迹的分布约束是必要的； 如果 GRPO-only 接近 GRPO+OPD，则说明主要收益来自 8-rollout 组内优化，OPD 的边际收益有限。

2. 变量控制

本实验只移除 SDPO/OPD teacher 分支，其余条件尽量与全量 GRPO+SDPO 对照保持一致。

维度 GRPO-only 设置 控制理由
Base model /mnt/jfs/copilot/lhb/checkpoint/opensource/Qwen3-VL-4B-Instruct 从同一个 4B base 出发，避免 warm-start 差异。
训练集 /data/codes/gui_grounding/data/rs_full/rs_train.jsonl 使用全量数据，不用 smoke 或 subset。
测试集 /data/codes/gui_grounding/data/rs_full/rs_test.jsonl 与前面全量实验保持同一测试分布。
Rollout 数 num_generations=8 保持“一次 rollout 8 个 bbox”的设定。
Reward bbox-geometry 只用几何 reward 优化 bbox，不引入 teacher。
SDPO/OPD --use_sdpo false，不传 teacher_model，不建 opsd_mask_dir 确保这是纯 GRPO 对照，而不是弱化版 GRPO+SDPO。
Batch / LR 2 nodes × 7 GPUs × bsz4 × grad_acc2 = generation_batch_size 112，lr=2e-6 沿用两节点 4B 全量训练配置，减少训练效率变量。
评估 训练结束后对最新 checkpoint 跑 greedy 测试集评估 先看单次采样真实部署性能，再按需补 best-of-8 oracle。

5. 结果记录指标

主指标 IoU@0.5：最直接对齐前面全量实验比较。
辅助指标 mIoU、IoU@0.7：观察定位精度是否整体提升。
格式稳定性 parse_rate、valid_rate：判断 GRPO 是否破坏 bbox 输出格式。

建议训练完成后记录：

cat /mnt/jfs/copilot/lhb/artifacts/rs/rs-sd/eval/<run_name>/checkpoint-*/summary.json

如果 GRPO-only greedy 指标较低，但 best-of-8 oracle 较高，说明模型会采到好框，但还没有把好框概率集中到单次输出；这正是 OPD/teacher 分布校正可能发挥作用的地方。

6. 结果判读

现象 解释 下一步
GRPO-only ≈ GRPO+OPD 主要收益来自 8-rollout 组内优化，teacher 校正边际小。 优先优化 GRPO reward、采样温度、num_generations、训练步数。
GRPO-only 明显低于 GRPO+OPD OPD/teacher 对失败轨迹有实质指导作用，能帮助模型把概率质量转向正确 bbox。 继续做 selective teacher、teacher/ref refresh、失败样本路由阈值消融。
GRPO-only 高于 GRPO+OPD teacher 分布可能过强或不稳定，干扰了 GRPO 的 reward 优化。 降低 sdpo_lambda，仅对低 IoU 样本启用 teacher，或改用更保守的 KL top-k。
GRPO-only parse/valid 下降 纯 RL 可能牺牲输出格式稳定性。 增加格式 reward 或保留轻量 SFT/teacher 格式约束。
