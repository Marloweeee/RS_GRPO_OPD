BBox-SRPO：Sample-Routed OPSD 遥感定位实验计划

基于 SRPO 的 sample routing 思想，重新设计遥感 bbox grounding 的 OPSD 强化训练： student 对同一图文 prompt 采样 8 个 bbox，几何 reward 判断轨迹质量； 高质量轨迹走 GRPO，低质量轨迹走 entropy-weighted OPSD / teacher correction； teacher 不再无差别蒸馏所有样本，而只服务需要纠偏的样本。

任务：遥感 referring bbox grounding 方法：BBox-SRPO / Sample-Routed OPSD 基础：OPSD + GRPO + SRPO routing 候选数：K=8 核心指标：greedy IoU@0.5 更新日期：2026-05-21

1. 背景与关键观察

当前 student checkpoint 已经能在 8 次采样中产生明显优于 greedy 的 bbox。 这说明模型的候选空间中存在高质量定位结果，但单次策略没有稳定选择它们。

设置 模型 是否使用 teacher 是否使用 GT 选择候选 IoU@0.5
greedy student student checkpoint-80 否 否 0.6562
best-of-8 oracle student checkpoint-80 否 是 0.7335
核心目标： 不是继续证明 best-of-8 上限高，而是让训练后的 greedy student 吸收高质量候选的偏好，使单次输出靠近 best-of-8 上限，并缩小 oracle gap。
主线纠正： 本实验的主方法是 K=8 rollout + GRPO 组内优化 + SDPO/OPSD failed 轨迹教师纠偏。 SFT/DPO 只作为离线诊断或历史误入分支，不作为主实验。

2. SRPO 给本工作的启发

SRPO 的核心是把 group-relative optimization 和 self-distillation 通过 sample routing 统一起来： 正确样本走 GRPO，错误样本借助 teacher/self-distillation 做 dense correction。 它强调不应把 GRPO 和蒸馏简单混在所有样本上，而应按样本质量选择监督信号。

SRPO 论文思想 遥感 bbox grounding 中的对应设计
同一个 prompt 采样一组 rollout 每张遥感图和 referring expression 采样 8 个 bbox response
用 reward 判断正确 / 错误 rollout 用 IoU、中心偏移、面积比例、长宽比等几何 reward 评价 bbox
correct rollout route 到 GRPO 高 IoU 且高于组内均值的 bbox 用 GRPO 强化
incorrect rollout route 到 SDPO / teacher correction 低质量 bbox 用 hint teacher / OPSD 纠正坐标分布
teacher signal 做 entropy-aware dynamic weighting 坐标 digit 权重乘 teacher confidence，低熵 token 高权重，高熵 token 降权
避免所有样本同时混合 GRPO 和蒸馏 采用 sample routing：good 走 GRPO，failed 走 OPSD，ambiguous 弱更新或跳过
不能照搬的地方： SRPO 多用于文本 reasoning / tool use，正确性常接近二值； 遥感 bbox 的质量是连续值，不能只按 correct / incorrect 路由，必须引入 IoU 阈值和 reward margin。

3. 与原 OPSD / GRPO 的区别

方法 优点 问题 本实验中的处理
纯 OPSD teacher hint 提供 dense token supervision，对坐标数字友好 可能干扰已经正确的 student rollout；teacher hint 过强会引入分布差异 只对 failed / low-quality 路由样本使用 teacher correction
纯 GRPO 直接优化几何 reward，保留 on-policy 性质 sequence-level reward 对坐标 token 纠错较粗；早期失败样本难学 高质量 rollout 走 GRPO，失败样本交给 teacher dense correction
简单混合 GRPO + OPSD 实现简单 所有 rollout 同时吃两种信号，可能优化目标冲突 作为消融对照，而不是主方法
BBox-SRPO 根据 rollout 质量路由监督信号，兼顾 reward alignment 与 teacher correction 需要稳定 routing、teacher entropy 估计和 correction rate 控制 本计划主实验

4. 核心算法：BBox-SRPO Routing

对同一 prompt 采样 8 个 student bbox response：

y1, y2, ..., y8

计算每条轨迹的 geometry reward 和 IoU：

r1, r2, ..., r8
iou1, iou2, ..., iou8

组内 baseline 和 advantage：

mean_r = mean(r1...r8)
std_r  = std(r1...r8)
adv_i  = clip((r_i - mean_r) / (std_r + eps), -adv_clip, adv_clip)

路由规则

is_good_i =
    valid_box_i
    and iou_i >= tau_good
    and reward_i >= mean_r

is_failed_i =
    (not valid_box_i)
    or iou_i < tau_fail
    or adv_i < -delta

is_ambiguous_i =
    not is_good_i and not is_failed_i
路由类别 条件 训练信号 意图
Good IoU >= tau_good 且 reward >= group mean GRPO 正向强化 保留 student 自己探索到的好 bbox
Failed invalid、IoU < tau_fail 或明显低于组内均值 GRPO 负向抑制 + entropy-weighted OPSD correction 压低错误轨迹，同时用 teacher dense signal 纠偏
Ambiguous 介于 good 和 failed 之间 弱 GRPO、低权重更新，或第一版跳过 teacher 避免强化“烂中较好”的不可靠 bbox
相比“高于组内均值即正样本”，BBox-SRPO 必须同时使用组内相对优势和绝对质量阈值。 这样能避免 8 个 rollout 全部很差时仍然强行强化其中相对较好的错误 bbox。

5. Teacher Correction 设计

5.1 teacher 信息来源优先级

借鉴 SRPO 中 successful sibling 可作为 teacher information 的思想，teacher/correction target 的优先级如下：

if group_best_iou >= tau_good:
    correction_target = best sibling student rollout
elif hint_teacher_available:
    correction_target = hint teacher answer
else:
    correction_target = GT bbox JSON answer

这样可以优先保持 on-policy：student 自己探索出好 bbox 时，不直接用 GT 或 hint teacher 覆盖； 只有整组探索失败时才引入更强的 teacher/GT correction。

5.2 failed rollout 是否直接做 bad-prefix KD

对 bbox 来说，bad rollout 的错误通常集中在坐标数字 token。 如果直接在错误坐标前缀上做无权重 KD，teacher 可能在偏离真实 bbox 的前缀下给出噪声分布。 但 SRPO 的启发是：可以让 teacher 在 enriched context 下重评 failed trajectory，只要使用 entropy-aware weighting 控制噪声。

第一版建议： failed rollout 进入 OPSD correction 时，必须使用 teacher entropy weighting； 不做未加权的 bad-prefix KD。

5.3 entropy-weighted OPSD

raw_w_t =
    digit_position_weight_t
    * exp(-beta_entropy * H_teacher_t)

w_t = raw_w_t / mean(raw_w over valid correction tokens)
组成 含义
digit_position_weight 坐标数字 token 权重，例如 norm-1000 下最多按 3 位数字加权。
exp(-beta_entropy * H_teacher) teacher 越确定，权重越高；teacher 高熵位置自动降权。
batch/token normalization 保持 correction loss 的尺度稳定，避免动态权重改变整体学习率。
这与本地 OPSD 已有的 uniform-entropy / linear-entropy 思路一致， 但需要升级为 routing 后只在 failed/correction branch 使用，并对权重做归一化。

6. Reward 设计

第一版沿用已在 best-of-8 eval 中验证过的几何 reward：

reward =
  0.10 * parse_ok
+ 0.10 * valid_box
+ 0.50 * IoU
+ 0.15 * center_score
+ 0.10 * area_ratio_score
+ 0.05 * aspect_ratio_score

第二轮可加入阈值奖励作为消融：

reward_v2 =
  reward
+ 0.10 * 1[IoU > 0.5]
+ 0.05 * 1[IoU > 0.7]
第一版仍建议使用连续 reward，避免训练早期过度依赖硬阈值。 阈值奖励主要用于加强 IoU@0.5 / IoU@0.7 指标对齐。

7. 训练目标

7.1 GRPO branch

L_grpo =
  - mean_i [
      min(
        ratio_i * adv_i,
        clip(ratio_i, 1 - eps, 1 + eps) * adv_i
      )
    ]

其中：

ratio_i = exp(logprob_new(y_i | x) - logprob_old(y_i | x))

如果第一版工程上暂时拿不到 old logprob，可先做简化版本：

L_pg = - mean_i [ stopgrad(adv_i) * logprob_student(y_i | x) ]

7.2 OPSD / SDPO correction branch

L_correction =
  weighted_jsd_or_kl(
    student_logits_on_failed_or_target,
    teacher_logits_with_hint,
    token_weights = entropy_weighted_digit_weights
  )

7.3 总损失

L =
  L_grpo_or_pg
+ lambda_sdpo      * L_entropy_weighted_sdpo_failed
+ beta_kl          * KL(student || reference_student)
+ lambda_format    * L_format
损失项 启用对象 作用
L_grpo_or_pg 所有 rollout 或 good/failed 参与，ambiguous 可低权重 组内相对强化，good 增强、failed 压低
L_entropy_weighted_sdpo_failed failed / correction branch teacher 对错误或失败样本提供 dense 坐标纠偏
KL(student || reference) 所有训练样本 防止 RL 引起格式和语义漂移
L_format 格式样本或所有 bbox answer 维持 {"bbox_2d":[...]} 可解析输出

Stage 3：正式在线 BBox-SRPO / Sample-Routed OPSD

最终版本在训练过程中实时采样并路由：

1. 对每个 prompt 采样 K=8 个 student bbox response
2. 解析 bbox，计算 geometry reward 和 IoU
3. 组内 advantage normalization
4. 根据 good / failed / ambiguous 做 sample routing
5. good route 到 GRPO
6. failed route 到 entropy-weighted OPSD correction
7. correction target 优先 best sibling，其次 hint teacher，最后 GT answer
8. 加 KL/reference 和 format loss
9. 监控 routing ratio、teacher entropy、greedy metric、oracle gap

Stage 4 设想：迭代式自蒸馏与 checkpoint bootstrapping

当前实验出现了一个重要模式：模型先通过已有 RS checkpoint 获得一个较强的候选分布， 再基于该 checkpoint 继续做 K=8 rollout、route、teacher correction，greedy 性能继续上升。 这可以被理解为一种 iterative self-distillation / self-improvement loop： 每一轮都把“上一代模型在多次采样中偶尔能做到的能力”压缩回下一代模型的单次 greedy 输出。

新增证据： checkpoint-348 的 best-of-8 oracle 已从 checkpoint-80 的 mIoU=0.6502 / IoU@0.5=0.7335 / IoU@0.7=0.5874 提升到 mIoU=0.6919 / IoU@0.5=0.7736 / IoU@0.7=0.6705。 这说明 2 epoch 继续 GRPO+SRPO/SDPO 不只是把原有 best-of-8 能力压缩到 greedy， 还扩大了模型在 K=8 采样下能到达的候选质量上限。 IoU@0.5 oracle gap 从 0.0773 变为 0.0716，说明 greedy 追上了一部分上限； 同时 oracle 本身上移，说明下一轮 checkpoint bootstrapping 仍有继续挖掘空间。 
base model
  -> RS supervised / weak self-distill
  -> ckpt_0

for round t in 0..T:
    ckpt_t rollout K=8
    route good / failed / ambiguous
    good: reinforce self-discovered correct bbox
    failed: use sibling / teacher / GT correction with entropy weighting
    train greedy policy
    evaluate greedy and oracle@8
    ckpt_{t+1} = best checkpoint under validation metric
为什么可能继续提升 在 bbox grounding 中的具体含义 需要监控的信号
候选空间质量随 checkpoint 改善 更强的 ckpt 能在 K=8 中产生更多 high-IoU sibling，teacher/GT 依赖减少。 best-of-8、good route ratio、best-sibling correction ratio。
greedy 压缩多采样能力 训练目标不是扩大采样上限，而是把 best-of-K 的定位偏好压回单次输出。 oracle gap、capture ratio、greedy IoU@0.5 / IoU@0.7。
failed route 提供局部坐标纠偏 坐标 digit token 的 dense correction 能修正 GRPO sequence reward 不够细的问题。 sdpo/loss、teacher entropy、failed route ratio、valid_rate。
teacher 可逐步退火 越到后期越应减少 GT/hint teacher 介入，转向 sibling-first 自蒸馏，避免 teacher overfit。 teacher correction ratio、validation gap、small/medium/large 分桶收益。
深挖时的关键风险： 迭代自蒸馏不应无脑反复训练同一测试集指标。 每轮必须使用独立 validation 选 ckpt，并保留最终 test 只做一次或少数几次确认； 否则容易把“持续提升”误读为真实泛化提升。 同时需要监控 oracle gap：如果 greedy 提升但 oracle@8 不升，说明主要是压缩成功； 如果 oracle@8 提升但 greedy 不升，说明探索变强但单次策略没有学会选择。
推荐下一步： 把迭代自蒸馏设计成 3 轮小预算曲线，而不是一次性无限训练： ckpt80 -> round1(e1/e2) -> round2(e1) -> round3(e1)。 每轮都评估 greedy、sample-one、best-of-8、route ratio 和面积分桶。 如果 round2/round3 仍能缩小 oracle gap，说明这种 checkpoint bootstrapping 值得作为主线方法深挖； 如果提升停滞或 small-object 退化，则应转向更强的 small-object reward / hint teacher 策略。

11. 推荐超参与阈值

参数 第一版建议 说明
K 8 与 best-of-8 上限实验保持一致。
temperature 0.7 提供探索但不过度发散。
top_p 0.95 与现有 best-of-8 评测保持一致。
tau_good 0.5 good route 的 IoU 阈值，对齐 IoU@0.5 主指标。
tau_fail 0.3 低于该阈值视为明确失败，进入 correction branch。
delta 0.5 advantage 低于 -delta 时可视为明显低于组内水平。
adv_clip 2.0 避免极端 reward 主导训练。
clip_eps 0.2 GRPO/PPO-style ratio clipping。
beta_entropy 0.5 - 1.0 控制 teacher entropy 对 token 权重的影响。
lambda_correction 0.2 - 0.4 teacher correction 权重；过大容易退化成 teacher SFT。
beta_kl 0.01 - 0.03 防止 RL 和 correction 导致格式/语义漂移。
lambda_format 0.05 保持 bbox JSON 可解析性。

  1. 先实现 offline rollout pool 生成脚本，复用当前 eval_student.py --num_rollouts 8 的采样与 reward 逻辑。
  2. 在 200-500 样本 smoke 上生成 route label，检查 good / failed / ambiguous 比例是否合理。
  3. 在 rs_train 上生成 offline pool，完成 Stage 1 分布分析。
  4. 实现在线 GRPO+SDPO trainer，先跑 max_steps=1 smoke。
  5. 确认日志包含 reward、sdpo/route_failed、sdpo/loss、checkpoint 和 greedy eval。
  6. 优先跑 E3/E5/E7 三组核心实验。
  7. 最后跑 E8 sibling-first 和 E4/E6/E9 消融，支撑方法设计。

13. 风险与控制

风险 表现 控制方案
组内相对好但绝对仍差 8 个 rollout 全差，仍强化了“烂中较好”的 bbox。 good route 同时要求 IoU >= tau_good 和 reward >= mean。
teacher correction 过强 训练退化成 GT/hint teacher SFT。 监控 correction ratio，目标区间 20%-50%；优先使用 best sibling correction。
bad-prefix KD 噪声 teacher 在错误坐标前缀下给出不可靠分布。 failed correction 必须使用 entropy weighting；无权重 bad-prefix KD 只作为负面对照。
RL 破坏输出格式 parse_rate / valid_rate 下降。 加入 format reward、format SFT、小 KL，监控无效 bbox 比例。
只扩大探索，不提升 greedy oracle@8 上升，但 greedy 不升。 提高 good-route 的 GRPO 权重或延长在线训练，主看 oracle gap 是否缩小。
ambiguous 占比过高 大多数样本不进入明确 GRPO 或 correction。 调整 tau_good / tau_fail / delta，或引入 soft routing weight。

15. 最终方法表述

BBox-SRPO for Remote Sensing Grounding:
The student explores multiple bbox trajectories for each visual referring prompt.
Geometry reward routes high-quality trajectories to GRPO and low-quality trajectories to entropy-weighted OPSD correction.
Correction information is selected sibling-first, then hint-teacher, then GT, reducing unnecessary teacher interference and GT leakage.
The objective compresses best-of-K localization ability back into single-pass greedy inference.
