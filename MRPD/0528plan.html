MRPD 0528 主线补充实验计划

本文档聚焦三个最贴近 MRPD 主张的验证点：pass@8 gap reduction、路由机制分析、选择性蒸馏消融。目标是把“多轨迹中存在更好定位结果”进一步证明为“MRPD 能将组内优势和教师纠偏转化为单次 greedy 推理提升”。

路径：MRPD/0528plan.html 日期：2026-05-28 计划 数据集：RRSIS-D test 为主 模型：Qwen3-VL-4B 系列 checkpoint

0. 核心问题与当前证据缺口

已知事实 1
SFT 存在明显 best-of-8 上限
已有 gaussian hint pass@8：SFT first mIoU=0.7273，best@8 mIoU=0.8251，说明多轨迹里确实存在显著更好的 bbox。
已知事实 2
MRPD greedy 优于 SFT/GRPO
当前 RRSIS-D test：SFT=0.6809，GRPO-only 用户复核值=0.6862，MRPD gaussian metric refresh=0.6990，EMA0.98=0.7000。
缺口
还缺机制闭环
需要证明提升来自路由后的选择性纠偏，而不是采样噪声、普通 KD 或 hint 工程堆叠。

本文档的实验原则：所有对照尽量使用同一数据 split、同一评测脚本、同一采样参数、同一 checkpoint 选择规则。新增代码只做最小兼容改动，优先复用现有 `eval_teacher_hint_pass8.py`、训练日志中的 `sdpo/route_*` 指标，以及 MRPD 训练脚本。

2. 实验 A：pass@8 Gap Reduction

科学假设：如果 MRPD 真的学到了“组内更优轨迹”的定位偏好，那么训练后的 greedy mIoU 应该更接近该 checkpoint 自身的 best@8 上限；同时相对 SFT / GRPO-only，它应缩小 greedy 与 best@8 之间的 gap。

2.3 执行注意事项

  • 优先使用 tools/evaluation/eval_teacher_hint_pass8.py 的输出格式，因为它显式保存 first_*、best@8_* 和 per_sample.jsonl。
  • no-hint 也应使用同一脚本的 hint_mode=none 或 no_mask，避免旧 eval_student.py --num_rollouts 8 只输出 best 而没有 first 字段。
  • 最终表格不要只报 best@8，更要报 greedy、first@8、best@8、gap、gap reduction。核心结论应是 MRPD greedy 更接近自身或 SFT 的 best@8 上限。
  • 若 gaussian-hint first@8 低于 no-hint first@8，不应回避；这说明 privileged hint 改变了输入分布，但 best@8 仍可作为 teacher upper bound 分析。

3. 实验 B：路由机制分析

科学假设：MRPD 的收益来自“按 rollout 质量路由后，对失败轨迹施加教师纠偏”。因此需要证明三件事：失败轨迹真实存在；teacher 在 failed route 上相对 student 有更大优势；蒸馏信号主要落在 failed 或 ambiguous 样本，而不是无差别拉动所有样本。

1. rollout 学生模型生成每个 prompt 的 8 条 bbox 候选。
2. reward / IoU 根据解析框和 GT 计算 geometry reward、IoU、valid_box。
3. route 按 IoU、reward 与组内 advantage 标注 good / failed / ambiguous。
4. teacher 教师接收带 visual hint 的同一输入，提供分布级纠偏。
5. selective loss 默认仅 failed route 进入 teacher loss，避免好样本被拉回。

统计项 来源 输出字段 用途 可靠性要求

3.2 离线 teacher-student gap 分析

实验 ID 样本来源 比较对象 统计方式 核心指标 结论判据
B1 MRPD 训练时保存的 rollout 或重新离线生成 rollout pool student rollout bbox vs teacher-hint greedy bbox 按同一 prompt、同一 GT，先给 student rollout 标 route，再让 teacher 用 gaussian hint 生成 1 条 bbox。 每个 route 的 student IoU、teacher IoU、teacher-student gap、teacher 胜率。 在 failed route 上 teacher gap 应显著大于 good route；failed route 的 teacher 胜率应明显高于 50%。
B2 每个 prompt 的 8 条 rollout good sibling vs GT-hint teacher 若组内有 good sibling，比较 best sibling IoU 和 teacher IoU。 sibling_hit_rate、best_sibling_iou、teacher_iou、fallback_rate。 判断组内成功轨迹是否足够可靠，可支撑 sibling-hint 后续实验。
B3 failed / ambiguous / good 分桶 teacher loss mask 覆盖率 模拟当前 mask 逻辑，统计 failed-only、failed+ambiguous、all-samples 三种 scope 下进入蒸馏的样本比例。 mask_rate、route-specific mask_rate、预期 teacher loss 预算。 为实验 C 的训练消融提供解释，避免只看最终 mIoU。

3.3 推荐实现方式

  • 第一步先写 CPU 日志解析脚本：读取训练 log 中 Python dict 风格 metrics，输出 route_stats.json、route_stats.csv 和曲线图所需数据。
  • 第二步使用现有 rollout / eval 逻辑生成 route_analysis_per_sample.jsonl，每行包含 sample_id、rollout_id、route、student_iou、teacher_iou、teacher_minus_student、hint_mode、pred_bbox。
  • 若没有保存训练时 rollout，则重新用 SFT 或 MRPD ckpt 在 train/val 子集上采样 8 条，建议先用 RRSIS-D val 或 test 的 1000 条样本做机制分析，再扩展到全量。
  • 最终论文呈现建议：一张 route 分布曲线 + 一张 route 分桶 teacher gap 表 + 2 到 3 个可视化案例。

4. 实验 C：选择性蒸馏消融

关键实现提醒：当前代码中 sdpo_only_failed=true 表示 failed-only；sdpo_only_failed=false 实际表示 failed+ambiguous，因为 good route 仍被 mask 掉。因此如果要做真正的 all_samples，不能只改环境变量，必须增加一个显式的 distillation scope 参数。

4.1 最小消融矩阵

实验 ID 名称 蒸馏范围 代码/参数实现 其它训练设置 预期解释
C1 failed-only 只对 failed route 施加 teacher loss。 现有默认：sdpo_only_failed=true。 从 SFT checkpoint 初始化；GRPO+MRPD gaussian；metric/window refresh；1 epoch；save step=10。 主方法。若最优，说明只纠偏失败轨迹能保留学生已经学会的好轨迹。
C2 failed + ambiguous 对 failed 和 ambiguous route 施加 teacher loss，排除 good。 现有可实现：sdpo_only_failed=false。 与 C1 完全一致，只改蒸馏 scope。 验证 ambiguous 是否应当纳入纠偏；若略降，说明 ambiguous 中混有可接受样本，强行蒸馏会过度约束。
C3 all-samples good、ambiguous、failed 全部施加 teacher loss。 新增最小参数：sdpo_distill_scope=all，mask 全部非 skip 样本。 与 C1 完全一致，只改蒸馏 scope。 若低于 C1，证明 MRPD 不是普通全样本 KD；选择性路由是必要组件。

4.2 建议的最小代码改动

文件 改动 原因 风险控制
swift/rlhf_trainers/args_mixin.py 新增 sdpo_distill_scope: Literal['failed', 'failed_ambiguous', 'all'] = 'failed'。 用显式 scope 替代容易误解的 bool，保证实验命名和实际 mask 一致。 保留 sdpo_only_failed 兼容旧脚本；默认行为不变。
swift/rlhf_trainers/grpo_trainer.py 在 _attach_sdpo_batch 中按 scope 生成 sdpo_sequence_mask。 C1/C2/C3 的核心差异只应体现在 mask 上。 skip hint 的样本仍保持 0，避免 sibling skip 进入 teacher loss。

4.3 训练与评测输出

  • 每组训练完成后先做 greedy test：mIoU、IoU@0.5/0.6/0.7/0.8/0.9、parse_rate、valid_rate。
  • 每组同时解析训练日志：平均 route_good / route_failed / route_ambiguous、平均 mask_rate、平均 sdpo/loss、KL 曲线。
  • 若资源允许，对 C1 与 C3 再补 pass@8，观察 all-samples 是否降低 best@8 或 first@8。
  • 最终结论不能只写“C1 分数最高”，而要写“C1 在保持 good route 不被 teacher 过度拉动的同时，对 failed route 提供更集中纠偏”。

5. 汇总表与判断标准

验证点 成功标准 如果结果不符合预期 论文中如何诚实表述
pass@8 gap reduction MRPD greedy 高于 SFT/GRPO，并且 greedy-best@8 gap 小于 SFT 或 GRPO；或 MRPD first@8 高于 baseline first@8。 如果 MRPD best@8 也上升但 gap 不缩小，说明方法提升了整体采样质量，而非单纯压缩 gap。 改写为“MRPD improves the rollout distribution and greedy behavior”，不要强行声称完全转化 oracle 上限。
路由机制分析 failed route 中 teacher-student gap 最大，teacher 胜率高；good route gap 小或 teacher 不显著优于 student。 如果 teacher 在 good route 也明显更强，说明 teacher 可作为更通用监督，但选择性 mask 的必要性需要由 C 组消融证明。 强调 route 的作用是控制蒸馏预算和避免过度约束，而不必声称 teacher 只在 failed route 有价值。
选择性蒸馏消融 failed-only ≥ failed+ambiguous ≥ all-samples，或 failed-only 在 IoU@0.8/0.9 上最好。 如果 all-samples 更强，说明当前“选择性纠偏”不是最优主张，应调整方法为“teacher-regularized GRPO”，并把 route 作为分析而非核心组件。 负面结果也可接受，但必须据此调整论文 claim，不能继续主张 failed-only 是必要组件。

6. 推荐执行顺序

  1. 先做 CPU/脚本准备：统一 pass@8 输出字段；写 route log 解析脚本；确认 sdpo_distill_scope 的最小代码改动。
  2. 先跑评测，不先训练：补 SFT、GRPO-only、MRPD metric、MRPD EMA 的 no-hint / gaussian pass@8，生成 gap reduction 表。
  3. 再做机制统计：从已有 MRPD 训练日志解析 route 曲线；如果训练日志粒度不够，再离线生成 1000 条样本的 rollout route pool 做 teacher-student gap。
  4. 最后跑训练消融：C1/C2/C3 三组使用同一 SFT checkpoint、同一 gaussian hint、同一 metric refresh、同一训练步数和 eval 流程。
  5. 结果落盘：所有输出统一放在 /data/codes/gui_grounding/data/logs/eval/0528_mrpd_mainline/、/data/codes/gui_grounding/data/logs/training/0528_mrpd_mainline/ 或对应 rjob log 中；最终追加到 MRPD/0-SummaryOfExp.html。

最推荐第一批启动的任务：pass@8 全矩阵是纯评测，最直接服务论文主线；route log 解析是 CPU 任务，几乎不占 GPU；选择性蒸馏消融需要训练资源，建议等前两项确认无误后再起三组 2 机任务。
