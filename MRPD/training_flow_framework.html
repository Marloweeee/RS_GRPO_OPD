MRPD 训练流程框架

本文档描述当前代码中的整体训练流程，重点解释 8 条 rollout 轨迹拿到以后如何计算奖励、组内路由、GRPO 优化、OPSD 选择性蒸馏以及 teacher refresh / EMA 的作用。

1. 模型实例与职责

Student / Policy

主训练模型。它参与 GRPO loss 和 OPSD loss 的反向传播，训练过程中持续更新。

vLLM Rollout Server

加载 student 权重的推理副本，用于 on-policy 生成 bbox。训练中通过 /update_flattened_params/ 同步最新 student 参数。

Reference Model

GRPO 的 KL 锚点，通常从 SFT ckpt 初始化并保持不变，避免策略过度偏离 SFT 分布。

Teacher Model

OPSD 的视觉提示教师。它看到带 hint 的图像/文本，给低质量 rollout 提供分布级纠偏。

Reward Function

解析 bbox 后计算 IoU、中心、面积、长宽比等几何奖励，用于 GRPO 组内优势和 OPSD 路由。

Hint Processor

根据 GT bbox 生成 gaussian、zoom_in、jitter_box、soft_window 等视觉提示图，供 teacher 输入使用。

2. 单个训练 step 的主流程

采样 prompt 组

DataLoader 取一批遥感 grounding 样本，每个 prompt 对应一个 GT bbox。

vLLM 生成 N=8

student rollout server 对同一 prompt 采样 8 个候选 bbox。

解析与奖励

解析 JSON bbox，计算 valid_box、IoU、geometry reward。

组内归一化

同一 prompt 的 8 个 reward 计算 mean/std，得到相对 advantage。

路由

按 IoU、valid_box、reward 是否高于组均值、advantage 是否过低分成 good/failed/ambiguous。

GRPO + OPSD

good 轨迹主要由 GRPO 强化；failed 轨迹进入 teacher 蒸馏纠偏。

更新参数

反向传播更新 student；必要时刷新/EMA teacher，并同步 student 到 vLLM。

3. Rollout 后的路由规则

当前代码在 swift/rlhf_trainers/grpo_trainer.py::_prepare_sdpo_routing 中实现路由。对每组同 prompt 的 N 个候选，先计算组内 reward 均值和标准差，再给每条轨迹打 route。

good route

条件：bbox 有效，IoU ≥ sdpo_tau_good，且 reward ≥ 组内均值。

含义：这条轨迹已经比组内平均水平好，应主要通过 GRPO 增强其概率。

failed route

条件：bbox 无效，或 IoU < sdpo_tau_fail，或 advantage < -sdpo_delta。

含义：这条轨迹质量明显差，需要 teacher 用视觉提示分布来纠偏。

ambiguous route

条件：既不是明显 good，也不是明显 failed。

含义：默认不强行蒸馏，避免 teacher 对边界样本施加过强约束。

参数默认值作用代码来源
num_generations8（当前实验配置）同一个 prompt 一次 rollout 8 条候选 bbox，并在这 8 条内部计算组均值、组标准差和相对 advantage。训练脚本传入；路由函数按 num_generations 分组。
sdpo_tau_good0.5IoU 达到该阈值后，才可能进入 good route。args_mixin.py
sdpo_tau_fail0.3IoU 低于该阈值时，直接进入 failed route。args_mixin.py
sdpo_delta0.5组内标准化 advantage 低于 -0.5 时，即使 IoU 未低于失败阈值，也视为明显差样本。args_mixin.py
sdpo_only_failedtrueOPSD 蒸馏主要施加在 failed route 上；good route 主要交给 GRPO 提升概率，ambiguous route 默认不强行蒸馏。args_mixin.py 与训练脚本
sdpo_targetrollout教师纠偏时以 rollout response token 为对齐目标，teacher 看到带视觉提示的输入后给出分布约束。args_mixin.py 与训练脚本

精确判定逻辑：对同一 prompt 的 8 条 rollout，先计算每条样本的 IoU、bbox 是否可解析有效、reward，以及组内 adv=(reward - group_mean)/(group_std + 1e-6)。若 bbox 有效、IoU ≥ 0.5 且 reward ≥ group_mean，标记为 good；若 bbox 无效、或 IoU < 0.3、或 adv < -0.5，标记为 failed；剩余所有有效但边界不明确的样本标记为 ambiguous。

ambiguous 会出现的情况：它不是解析失败，也不是明显坏样本，但又不足以作为组内优样本强化。典型情况包括：IoU 位于 [0.3, 0.5) 的中等 bbox；或者 IoU 已经超过 0.5，但 reward 低于组均值，同时 advantage 还没有低到 -0.5 以下。

例子：假设某个 prompt 的 8 条候选中，组内 reward 均值为 0.70、标准差为 0.10。一条候选 bbox 有效，IoU 为 0.42，reward 为 0.68，则 adv=(0.68-0.70)/0.10=-0.20。它的 IoU 没达到 good 的 0.5，但 IoU 也没有低于 failed 的 0.3，adv 也没有低于 -0.5，因此会被标记为 ambiguous。再比如 bbox 有效、IoU 为 0.56、reward 为 0.66，adv 为 -0.40，由于 reward 低于组均值，不能进 good；但 adv 没有低于 -0.5，也不会进 failed，所以同样是 ambiguous。

5. Teacher 输入如何构造

复制原始样本

teacher_data 从 student rollout 样本深拷贝而来。

添加 hint 文本

例如 “target is located within the green rectangle”。

生成 hint 图像

基于 GT bbox 生成 gaussian / zoom_in / jitter_box / soft_window 图像。

替换 image path

teacher 的图像路径替换成 hint 后的缓存图。

teacher forward

teacher 对相同 response token 给出更强分布指导。

关键点：teacher 不是另一套外部大模型，而是同架构 Qwen3-VL-4B 的一个实例。它强的地方来自视觉提示和参数刷新/EMA，而不是模型规模更大。

6. Teacher 更新策略

策略行为优点风险当前实验状态
No refreshteacher 固定为 SFT ckpt。稳定，不会追随 student 噪声。训练后期 teacher 可能滞后。已完成，test mIoU 0.6981。
Fixed step refresh固定 step=80 同步一次 student 到 teacher。简单可复现。刷新时机拍脑袋，可能错过更好窗口。已完成，test mIoU 0.6987。

7. 为什么这个流程对应论文主张

  • SFT 解决格式和基础对齐：没有 SFT，bbox JSON 输出、坐标尺度和基础定位都不稳定。
  • GRPO 解决“选择更好轨迹”：同一 prompt 的 8 个 rollout 中通常存在更好 bbox，GRPO 把组内相对优势转成概率更新。
  • OPSD 解决“失败轨迹如何纠偏”：对 failed route，不直接模仿错误 rollout，而让视觉提示 teacher 给出分布级修正。
  • Teacher refresh/EMA 解决“教师滞后”：teacher 不能太旧，否则后期指导无效；也不能无约束追随 student，否则失去稳定锚点。
  • 部署仍是单模型：训练时有 student、teacher、ref、vLLM rollout，最终部署只用 student greedy 推理，不需要 pass@8。
