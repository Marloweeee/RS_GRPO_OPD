MRPD Sibling-Hint SDPO 实验方案

目标是在现有 GT-hint SDPO 基础上，验证一种更少依赖 oracle 视觉提示的 sibling-guided teacher 方案：用同组 rollout 中的高质量 sibling bbox 构造 teacher 视觉提示，再修正 failed rollout。

训练：GRPO + SDPO/MRPD 核心变量：sibling hint source 正式评测：student greedy no-hint Fallback：无 good sibling 时使用 GT hint

1. 核心假设

假设：同一个 prompt 的 K 条 rollout 中，如果存在一个高质量 sibling，它的预测 bbox 可以作为 teacher 的弱视觉提示，帮助 teacher 对 failed sibling 给出更贴近正确区域的 token 分布。这样既保留 MRPD 对 failed 样本的纠偏能力，又减少 teacher 输入直接依赖 GT bbox 的程度。

现有 GT-hint SDPO

teacher 视觉提示由 GT bbox 生成，强、稳定，但属于 privileged teacher。

Sibling-hint SDPO

teacher 视觉提示由同组 best sibling 的预测 bbox 生成，更像 on-policy self-correction。

Fallback GT-hint

当一组 rollout 没有合格 sibling 时，为保证训练覆盖率，回退到当前 GT-hint teacher。

2. 单组 Rollout 流程

生成 K 条 rollout

student 对同一 prompt 采样 K 个候选 bbox，默认 K=8。

计算 bbox / IoU / reward

解析每条 response，计算 valid_box、IoU、geometry reward。

选择 best sibling

从满足 IoU ≥ tau_good 的候选中，按 reward / IoU 最高选出 hint source。

定位 failed rollout

沿用现有 route 规则，找出需要 teacher 修正的 failed 样本。

构造 teacher hint

用 best_sibling.pred_bbox 生成 teacher 视觉提示图和弱提示文本。

无 sibling fallback

如果没有 good sibling，则使用 GT hint，保证强性能与训练密度。

计算 SDPO loss

teacher 在 hint 条件下对 failed response tokens 做 forward，和 student logits 做 top-k KL。

3. 具体算法定义

  1. 对每个 prompt 生成 K 个 rollout，保存每条候选的 response text、response token ids、pred bbox、valid_box、IoU、geometry reward。
  2. 按当前 SDPO 路由规则计算 good、failed、ambiguous。
  3. 在同组候选中筛选 valid_box == true 且 IoU >= tau_good 的候选。
  4. 如果存在合格候选，选择 best_sibling。主排序建议为 (reward, IoU, valid_box)，因为 reward 已综合 IoU、中心、面积、长宽比；如需更偏 IoU，可用 (IoU, reward, valid_box) 做 ablation。
  5. 对每条 failed rollout，student 输入保持不变：原图 + 原 prompt + failed response tokens。
  6. teacher 输入改造：用 best_sibling.pred_bbox 生成 hint 图；文本提示使用弱语气，不写 correct。
  7. 如果该组没有合格 best_sibling，强性能版本回退到 GT hint，沿用当前 MRPD 的 teacher 输入构造方式。
for group in rollout_groups:
    for cand in group:
        cand.pred_bbox = extract_bbox(cand.text)
        cand.iou = iou(cand.pred_bbox, gt_bbox) if cand.valid_box else 0
        cand.reward = geometry_reward(cand.pred_bbox, gt_bbox)
        cand.route = route_by_current_sdpo_rule(cand, group)

    good_pool = [
        cand for cand in group
        if cand.valid_box and cand.iou >= tau_good
    ]

    if good_pool:
        hint_source = max(good_pool, key=lambda x: (x.reward, x.iou, x.valid_box))
        hint_source_type = "sibling"
        hint_bbox = hint_source.pred_bbox
    else:
        hint_source_type = "gt_fallback"
        hint_bbox = gt_bbox_norm_or_pixel

    for cand in group:
        if cand.route != "failed":
            continue
        student_input = original_image + original_prompt + cand.response_token_ids
        teacher_input = render_hint(image, hint_bbox, source=hint_source_type) \
            + weak_hint_text(hint_source_type) + cand.response_token_ids
        sdpo_loss += topk_teacher_kl(student_logits, teacher_logits)

4. Teacher 文本与视觉提示

Hint 来源 视觉提示 bbox 推荐 mask mode Teacher 文本 原因
Sibling hint best_sibling.pred_bbox soft_window 或 jitter_box Hint: The target is likely within the highlighted region. best sibling 仍有噪声，不应把预测框描述为正确答案。弱提示能降低错误边界被 teacher 过拟合的风险。
Sibling box hint best_sibling.pred_bbox jitter_box Hint: The target is approximately within the highlighted box. 当需要更强空间定位信号时使用，但文本必须使用 approximately。
GT fallback solution.arguments.coordinate 沿用当前 gaussian / zoom_in Hint: The answer is located within the green rectangle. 无 good sibling 时保留当前强 teacher，避免大量 failed 样本没有 SDPO 信号。

注意：即使用 sibling bbox 做 teacher 视觉提示，训练时仍然使用 GT 来计算 IoU、reward、good sibling 选择和 failed 路由。因此它不是完全无 GT 的训练方法；它减少的是 teacher 输入中直接使用 GT bbox 的比例。

需要改动的核心位置

  • swift/rlhf_trainers/args_mixin.py：注册 sibling hint 相关参数。
  • swift/rlhf_trainers/grpo_trainer.py::_prepare_sdpo_routing：在每个 rollout group 内缓存 best sibling 信息，例如 _sdpo_sibling_hint_bbox、_sdpo_hint_source_type。

  • 训练脚本：新增 SDPO_HINT_SOURCE=sibling_gt_fallback、SDPO_SIBLING_SELECT_METRIC=reward 等环境变量。

7. 关键日志与判断指标

覆盖率指标

sibling_hit_rate：有 good sibling 的 group 比例。若过低，sibling 方案会主要退化为 GT fallback。

fallback 指标

gt_fallback_rate：无 good sibling 而回退 GT hint 的 group 比例。

提示质量指标

sibling_hint_iou_mean：被选为 hint source 的 sibling bbox 平均 IoU。

路由指标

route_good、route_failed、route_ambiguous，确认 sibling 方案是否改变 failed 占比。

训练指标

sdpo_loss、GRPO reward、KL、completion length、clipped ratio。

正式评测

只使用 student no-hint greedy evaluation：num_rollouts=1、temperature=0.0。

8. 预期现象与风险控制

现象 解释 处理方式
训练早期 sibling_hit_rate 低 student 还不稳定，同组 8 条里未必有 IoU ≥ 0.5 的候选。 使用 GT fallback 保持训练密度；或前 N step 使用 GT-hint warmup，再切 sibling-hint。
sibling bbox 边界不准 IoU ≥ 0.5 只说明大致定位正确，不代表边界精确。 优先用 soft_window 弱视觉提示；文本使用 likely / approximately，不写 correct。
性能低于 GT-hint baseline GT-hint teacher 是强 oracle，sibling-hint 是 noisy teacher。 看 gap 是否缩小、fallback rate 是否下降、是否带来更清晰的论文叙事。
性能超过 GT-hint baseline sibling hint 可能减少 GT 过强提示导致的 train/test mismatch，使 teacher 分布更接近 student 可利用的信息。 重复不同 seed，并检查是否存在 test-set checkpoint selection。

9. 最小可执行版本

建议第一版只做一个主实验：sdpo_hint_source=sibling_gt_fallback，mask_mode=soft_window，select_metric=reward。如果有 good sibling，就用 sibling bbox 做弱视觉提示；如果没有，就 fallback 到当前 GT gaussian/hint teacher。这样改动最小、性能风险低，也能直接和现有 MRPD baseline 对比。

  • 训练数据：继续使用 rs_full/rs_train.jsonl。
  • checkpoint 选择：使用 rs_val.jsonl，不要用 test 选最佳 checkpoint。
  • 最终报告：只在 rs_test.jsonl 上做一次 student no-hint greedy 测试。
  • 核心对比：Baseline MRPD GT-hint vs Sibling+GT fallback vs Sibling-only。
