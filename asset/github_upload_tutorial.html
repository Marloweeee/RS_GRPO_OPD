GitHub 发布教程

将 GUI-SD / RS-GRPO-OPD 当前代码上传到 GitHub

目标仓库：https://github.com/Marloweeee/RS_GRPO_OPD。 本教程面向当前本地工程目录，重点是只上传源码、脚本和文档，避免把训练权重、缓存、日志、数据集和密钥推到公开仓库。

一、当前上下文

本教程假设你在下面这个目录中操作：

cd /data/codes/gui_grounding/GUI-SD-code-main
  • 本地分支main
  • 目标远端https://github.com/Marloweeee/RS_GRPO_OPD.git
  • 建议上传源码、swift/ 修改、tools/ 核心脚本、中文 README、实验方案 HTML、复现实验说明。
  • 不要上传output/、train_cache/、GUI-SD_scripts/train_cache/、checkpoint、日志、数据集、token、临时 cache。
安全底线：任何包含访问 token、wandb/swanlab 密钥、私有路径凭据、模型权重、训练数据或评测结果大文件的内容，都不要执行 git add、git commit 或 git push。

二、上传前检查

先确认工作区里有哪些改动，并识别明显的临时文件。

cd /data/codes/gui_grounding/GUI-SD-code-main
git status --short
git remote -v
git branch --show-current

当前本地可能会看到类似这些待处理项：

 M tools/training/launch_qwen3_4b_base_rsfull_grpo_sdpo_2node_rjob.sh
 M tools/training/run_qwen3_4b_base_rsfull_grpo_sdpo_2node_worker.sh
?? tools/training/1-launch_qwen3_4b_single_stage_rsfull_2node.sh
?? tools/training/launch_qwen3_4b_rsfull_grpo_sdpo_midrefresh_s80_2node_rjob.sh
?? tools/training/run_qwen3_4b_rsfull_grpo_sdpo_midrefresh_s80_2node_worker.sh
?? tools/evaluation/run_qwen3_4b_stage1_s80_eval_rjob.sh
?? =10.1
注意：=10.1 看起来像误生成的临时文件。上传前先用 file =10.1 和 sed -n '1,80p' =10.1 检查内容；如果确认无用，再删除或保持不加入 Git。

确认大目录是否已经被忽略。下面这些目录很大，通常只保留在本机或 /mnt 中：

git status --ignored --short output train_cache GUI-SD_scripts/train_cache result output_files
du -sh output train_cache GUI-SD_scripts/train_cache 2>/dev/null || true

三、确认 .gitignore 规则

当前仓库已经有忽略规则覆盖核心训练产物，但上传前仍建议再确认一次。关键规则应包括：

output/
train_cache/

GUI-SD_scripts/train_cache/

logging.jsonl

trainer_state.json
zero_pp_rank_*/
/data/
/guisd_data
/ground_benchmark/
/cache/

用 dry-run 看看 git add . 实际会加入哪些文件，不满意就先别提交：

git add --dry-run .
git ls-files -o --exclude-standard | sort | sed -n '1,200p'
判断标准：dry-run 列表里应该主要是源码、脚本、README、HTML 文档等文本文件；不应该出现 .safetensors、checkpoint-*、output/、train_cache/、images/ 或大体积 JSONL 数据。

四、提交前的轻量验证

上传仓库前至少做一次脚本语法检查，确保核心 shell 脚本没有明显语法错误。

bash -n tools/training/1-launch_qwen3_4b_single_stage_rsfull_2node.sh
bash -n tools/training/launch_qwen3_4b_base_rsfull_grpo_sdpo_2node_rjob.sh
bash -n tools/training/run_qwen3_4b_base_rsfull_grpo_sdpo_2node_worker.sh
bash -n tools/training/launch_qwen3_4b_rsfull_grpo_sdpo_midrefresh_s80_2node_rjob.sh
bash -n tools/training/run_qwen3_4b_rsfull_grpo_sdpo_midrefresh_s80_2node_worker.sh
bash -n tools/evaluation/run_qwen3_4b_stage1_s80_eval_rjob.sh

如果你只想检查所有 shell 文件，可以运行：

find tools -name '*.sh' -print0 | xargs -0 -n1 bash -n

五、选择要提交的文件

推荐先按模块显式 add，避免误把临时文件加进去。

git add .gitignore README.md REPRODUCE_RS.md
git add swift tools OPSD_Idea asset
git status --short

如果确认 =10.1 是误生成文件，不要 add。可以删除它：

rm -i '=10.1'
git status --short
如果远端仓库是公开仓库：提交前建议搜索敏感词。命中后不要直接推送，先确认是不是 token 或私有凭据。 
grep -RInE 'token|api_key|secret|password|passwd|wandb|swanlab|hf_|github_pat' \
  --exclude-dir=.git \
  --exclude-dir=output \
  --exclude-dir=train_cache \
  --exclude-dir=GUI-SD_scripts \
  . | sed -n '1,120p'

六、创建提交

当前工程的协作规范要求 commit message 尽量保留决策信息。可以使用下面这种结构：

git commit -m "Prepare RS-GRPO-OPD codebase for public handoff" \
  -m "Package the remote-sensing GRPO/SDPO experiment scripts, documentation, and repository hygiene so the project can be reviewed and reproduced from GitHub." \
  -m "Constraint: Do not publish checkpoints, datasets, logs, cache directories, or credentials" \
  -m "Rejected: Push local output and train_cache artifacts | too large and not source-controlled" \
  -m "Confidence: medium" \
  -m "Scope-risk: moderate" \
  -m "Tested: bash -n on updated training and evaluation shell scripts" \
  -m "Not-tested: Full training rerun from a fresh clone"

提交后检查最近一次提交：

git log --oneline -1
git show --stat --oneline HEAD

七、绑定 GitHub 远端

如果当前没有任何 remote，添加 origin：

git remote add origin https://github.com/Marloweeee/RS_GRPO_OPD.git
git remote -v

如果已经存在 origin，但指向旧仓库，则改成新地址：

git remote set-url origin https://github.com/Marloweeee/RS_GRPO_OPD.git
git remote -v

如果你更习惯 SSH，并且本机 GitHub SSH key 已配置好，也可以使用：

git remote set-url origin git@github.com:Marloweeee/RS_GRPO_OPD.git
git remote -v

八、推送到 GitHub

如果 GitHub 仓库是空仓库，直接推送当前 main 分支：

git push -u origin main

如果 GitHub 上创建仓库时勾选了 README、LICENSE 或 .gitignore，远端可能已经有一次初始化提交。这时先拉取并 rebase：

git pull --rebase origin main --allow-unrelated-histories
git push -u origin main
只在必要时使用 --allow-unrelated-histories：它用于合并两个没有共同祖先的历史，通常只发生在“本地已有 Git 历史，而 GitHub 新仓库又初始化了 README”的情况。

HTTPS 推送时，GitHub 不再接受账号密码作为 Git 密码。推荐两种认证方式：

  1. 使用 GitHub CLI：gh auth login，按提示登录后再执行 git push。
  2. 使用 Personal Access Token：用户名填 GitHub 用户名，密码位置填 token。

九、推送后验证

推送完成后，在本地和 GitHub 页面都做一次确认。

git status
git remote -v
git ls-remote --heads origin
  • GitHub 页面能看到 README.md、swift/、tools/、OPSD_Idea/ 等源码和文档。
  • GitHub 页面看不到 output/、train_cache/、checkpoint、.safetensors、日志和数据集。
  • README 中的路径说明清楚地区分了源码路径、本地数据路径和 /mnt checkpoint 路径。
  • 核心脚本命名和 tools/*/README.md 说明能让别人理解训练、评测和 rollout 的入口。

十、常见问题处理

1. remote origin already exists

git remote -v
git remote set-url origin https://github.com/Marloweeee/RS_GRPO_OPD.git
git remote -v

2. push 被拒绝，提示远端有你本地没有的提交

git pull --rebase origin main
git push -u origin main

如果是新仓库初始化 README 导致历史无共同祖先，再使用：

git pull --rebase origin main --allow-unrelated-histories
git push -u origin main

3. 文件太大或包含权重

如果还没提交，直接取消暂存：

git reset HEAD path/to/large-file
echo "path/to/large-file" >> .gitignore
git status --short

如果已经提交但还没有推送，可以软回退，移除大文件后重新提交：

git reset --soft HEAD~1
git reset HEAD path/to/large-file
echo "path/to/large-file" >> .gitignore
git commit

4. 不小心提交了 token 或密钥

立即处理：先撤销或轮换泄露的 token，再清理 Git 历史。仅从最新提交中删除文件不等于彻底消除泄露风险。

5. 需要确认某个文件是否会被忽略

git check-ignore -v path/to/file

十一、推荐的完整命令序列

下面是一套保守流程。执行前请先根据实际 git status 调整要 add 的文件。

cd /data/codes/gui_grounding/GUI-SD-code-main

git status --short
git remote -v

# 检查误生成文件，确认无用后再删除
file '=10.1' 2>/dev/null || true
sed -n '1,80p' '=10.1' 2>/dev/null || true
rm -i '=10.1'

# 确认不会上传大文件和缓存
git add --dry-run .
git status --ignored --short output train_cache GUI-SD_scripts/train_cache result output_files

# 语法检查
find tools -name '*.sh' -print0 | xargs -0 -n1 bash -n

# 分模块加入源码和文档
git add .gitignore README.md REPRODUCE_RS.md
git add swift tools OPSD_Idea asset
git status --short

# 提交
git commit -m "Prepare RS-GRPO-OPD codebase for public handoff" \
  -m "Package the remote-sensing GRPO/SDPO experiment scripts, documentation, and repository hygiene so the project can be reviewed and reproduced from GitHub." \
  -m "Constraint: Do not publish checkpoints, datasets, logs, cache directories, or credentials" \
  -m "Rejected: Push local output and train_cache artifacts | too large and not source-controlled" \
  -m "Confidence: medium" \
  -m "Scope-risk: moderate" \
  -m "Tested: bash -n on updated training and evaluation shell scripts" \
  -m "Not-tested: Full training rerun from a fresh clone"

# 绑定远端并推送
git remote add origin https://github.com/Marloweeee/RS_GRPO_OPD.git 2>/dev/null \
  || git remote set-url origin https://github.com/Marloweeee/RS_GRPO_OPD.git
git remote -v
git push -u origin main
